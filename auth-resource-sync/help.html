Auth Resource Sync

面板有两个能力，顶部页签切换：

  • 📦 资源同步：把权限资源（路由目录/菜单/按钮/字段权限/数据权限）从一个环境同步到另一个环境。典型场景：开发环境 → 测试环境。
  • 👤 用户权限同步：把某个账号的「应用 + 角色」复制到另一个账号 —— 同环境复制，或跨环境复制到另一个环境的同账号。

用户权限同步（应用 + 角色）

把「源账号」的应用与角色复制给「目标账号」。面板顶部切到 👤 用户权限同步。

典型场景：① 跨环境 —— dev 的某个账号想在 test 配成一样；② 同环境 —— 把自己的账号改成与另一个账号完全一致。

本功能会修改账号权限，执行前务必核对差异预览。 插件严格照抄页面「编辑用户」的提交行为：只改应用与角色， 基础信息（姓名/部门/手机号/邮箱）与数据权限/字段权限一律不动。

同步方式：自动判定，不用手选

方式由两个账号所在的环境自动决定，面板上会显示当前用的是哪条路径：

场景方式映射依据
两个账号在同一环境按 ID 直连直接用应用/角色 ID，最可靠
两个账号在不同环境按编码映射用 appCode 与 appCode + roleCode 到目标环境现场查 ID

为什么不用手选：同一环境下「按编码映射」只是把 ID 翻译成编码再翻回来，结果一样，反而多一个选错的机会。

怎么确认源数据是从哪个环境采集的：两个环境经常存在同名账号 （比如 dev 和 test 都有 liwei），只看账号名分不清是哪个环境。 所以每个输入框会按环境着色，并在旁边显示环境简称，鼠标悬停可看完整域名； 快照摘要里的环境名用的是同一个颜色。

配色规则（同一环境恒定同色）：dev 蓝 / test 绿 / uat 橙 / prod 红，其他环境按域名哈希取色。

改过输入框后，徽标会变成灰色的 ⚠ 待采集、框线也转灰 —— 因为此时框里的字不再属于任何一次采集，再沿用快照的环境色就等于把手输的 账号谎报成"采自某环境"。同时摘要行会标出「输入框已改，此快照待重新采集」， 预览被作废、执行按钮置灰。点一次「采集」让它重新对上即可。
「源:」/「目标:」那两行是已采集的快照，不是你输入框里的字。 输入框要点「采集」才会生效；快照是采集那一刻的定格，改账号权限后要重新采集才会更新。 跨环境时快照故意跨页面保留（否则你在 A 环境采的源数据一切页面就没了）， 所以它显示的一直是它当初被采集的那个环境，不会跟着你切页面而变。 单个快照超过 24 小时未重采会提示"建议重新采集"。

但输入框会跟着最新的采集结果走：你在任意一个标签页采集完， 其他已打开的标签页里的输入框会自动回填成刚采到的那个账号 （即使那里面原来还留着你更早输入的另一个账号），日志里也会记一条"已按新采集的快照回填"。 这样"在 test 采集、切到 dev 却因为框里还是旧账号而被拦住"就不会再发生了。 你自己动手打字之后，输入框不会被抢；直到下一次采集才会再同步。

跨环境怎么操作

  1. 在源环境打开用户管理页 → 填源账号 → 采集源账号
  2. 切到目标环境的同一页面 → 填目标账号 → 采集目标账号
  3. 两个都采集完会自动算差异，核对「将移除」的条目
  4. 点 ⚡ 执行同步 并确认
为什么不能直接照抄 ID：各环境是独立数据库，同一个角色在 dev 和 test 里的 ID 完全不同。 插件按应用编码（appCode）与角色编码（appCode + roleCode）到目标环境现场查 ID。 目标环境找不到相同编码时，该条目会列进「无法映射」并跳过 —— 插件不会按名称猜。

实测提醒：不同环境的编码并不保证一致（实测两个环境的角色编码只有约 7% 重合）， 所以跨环境出现较多「无法映射」是正常现象。

同环境怎么操作

在同一个页面上填两个不同的账号即可：「源账号」填要照抄的那个，「目标账号」填要被修改的那个， 各自点一次采集，然后核对差异。同一环境 ID 可直接比较，比跨环境更可靠。

差异预览怎么看

标记含义
✚ 新增执行后目标账号会获得该应用/角色
✖ 移除执行后会失去该应用/角色 —— 最需要核对的部分
⚠ 无法映射目标环境无相同编码，将被跳过，需人工在页面上处理
✔ 权限已完全一致无需写入；执行按钮置灰，不会发出任何请求
执行时还会额外拦一道：若目标账号就是你自己且本次会移除权限，会提示你 「可能把自己锁在权限管理页面之外」；若目标账号疑似超级管理员（账号名为 admin、 持有不属于任何应用的全局角色，或角色名含"超级管理员"），也会再提醒一次。 这两种情况建议换一个管理员账号操作。
执行后会自动回读校验：重新查询目标账号，确认应用与角色确实写成预期值， 并顺带确认基础信息未被改动。校验不通过会在日志里标红 —— 不要只看「提交成功」。

非开发/测试环境默认只读（可临时开启）

可写环境白名单：宿主首段含 dev / test / sit / uat， 另外放行 localhost 与 127.0.0.1； 生产与未知域名一律只读、禁止写入。

宿主形态识别为可写
mdmdev-auth.joyintoy.cn开发是
mdmtest-auth.joyintoy.cn测试是
sit-auth.joyintoy.cn集成测试是
uat-auth.joyintoy.cn验收测试是
stg-auth.joyintoy.cn预发否
auth.joyintoy.cn生产否
zt.joyintoy.cn生产否
其他任意域名未知否

公司主域（joyintoy.cn）下不带环境标记的宿主，一律按「生产」处理， 所以文案会直接说"这是生产环境"，而不是含糊的"未知环境"；非公司域的陌生网站标为"未知"，同样只读。

被拦时头部会显示 🔒 只读 徽标，两个面板的执行按钮都会变成不可用，鼠标悬停可看具体原因。 只读只挡写操作，采集与差异预览不受影响，你仍然可以先把差异看清楚。

确需在生产上同步时，点头部的 开启写入，需要两步确认： 先确认后果（会如实说明改动立即生效、哪些能撤哪些不能），再手动输入当前环境的完整域名。 开启后仅对当前环境、当前页面会话生效 —— 刷新页面即恢复只读， 不会一直留着一个"已经打开"的开关。

执行前会校验环境是否匹配

快照里的用户 ID、应用 ID、角色 ID、资源节点 ID 都只在采集它的那个环境里有意义。 所以执行时会比对「当前页面环境」与「目标快照所在环境」，不一致就禁止写入并明确提示， 避免把 A 环境的 ID 拿到 B 环境去改（那样可能改到完全不相干的账号或节点）。

常见触发场景：在 A 环境采集了目标账号，然后切到 B 环境页面处理别的事， 回来顺手点了执行。此时切回 A 环境页面（或在该页面重新采集）即可。 资源同步与用户权限同步都受这条约束。

大批量移除会再要一次确认

单次移除超过 20 项权限时（实测跨环境同步存在一次移除上百项的真实场景）， 预览顶部会出现红色横幅，执行时除常规确认框外，还必须手动输入目标账号名才能提交。 这一步挡的是"没看清就点确定"，而不是"想改但改错了"。

执行后可以一键撤销

用户权限同步执行成功后，按钮旁会出现 ↩ 撤销上次同步(账号名)， 点它就能把该账号的应用与角色恢复成执行前的那份值，并同样做回读校验。 这是「拿别人的权限覆盖自己」这条路径的兜底 —— 万一连自己的用户管理权限也被移除、 人已进不去权限页面，用它就能退回来。

行为说明
作用范围只保留最近一次同步，撤销成功即用掉；要重做就重新走一次同步
环境要求必须切回那次写入所在的环境；在别的环境按钮置灰，悬停可看原因
只读环境同样受只读/写入开关约束 —— 刷新页面后要先重新开启写入
大批量移除撤销若会移除超过 20 项，同样要求手动输入账号名
基础信息只动应用与角色，姓名/部门/手机号/邮箱等不会被改
撤销会被主动拦下的情况：如果该账号在你同步之后又被别人改过， 当前权限已不等于你上次写进去的值，插件会拒绝撤销并提示去页面人工核对 —— 因为无条件回写会把别人的合规修改一起抹掉。这种情况下没有"点一下就恢复"的捷径， 只能对着日志里的执行前记录手工还原。

资源同步没有撤销功能 —— 它按节点逐个 upsert，没有"执行前的整棵树快照"这个语义。 资源同步请依赖执行前的确认与同步队列核对。

资源同步：快速开始

1 打开权限管理页面

在浏览器中打开任意环境的权限管理系统（域名/MF_auth/），进入某个应用的「资源管理」标签页。

插件面板会自动出现在右下角（蓝色圆形按钮），点击展开。

2 采集源数据

在源环境页面中，点击面板的 采集源数据。插件会拉取当前应用完整资源树并缓存到本地。

3 采集目标数据

切换到目标环境的相同应用页面，点击 采集目标数据。

两个环境的 appId 可能不同，插件自动从页面请求中提取。若自动检测失败，可手动填入 appId。

4 选择同步模式并操作

插件提供两种模式，通过队列区顶部的 批量 / 单点 按钮切换。

5 执行同步

模式切换后，将任务加入对应队列，点击 执行队列 统一执行。

两种模式详解

🔵 批量同步模式（默认）

适用场景：把一整块功能从源环境「搬运」到目标环境。例如源环境有整套「供应商管理」模块（目录 + 菜单 + 按钮 + 字段），目标环境完全没有，需要整体迁移。

操作：勾选源节点（自动连带所有子孙）→ 目标树选择目标父节点 → 加入批量队列 → 执行队列。

行为：

  • 整棵子树一起同步（父节点 + 所有勾选子孙）
  • 按 BFS 顺序（先父后子）确保层级正确
  • 匹配到已有节点则更新，未匹配则新增

🟡 单点更新模式

适用场景：源和目标都已有同名节点，只想把源环境某个节点的配置「覆盖」到目标环境的对应节点。例如源和目标的「新增」按钮都存在，但权限字符、路径等字段不同，只想更新这一个按钮，不动它的子节点。

操作：

  • 在源数据树中只勾选一个要更新的节点（父节点不要连带勾选子节点）
  • 在目标数据树中点击选中对应的目标节点（类型必须一致）
  • 点击 更新到选中节点 加入队列
  • 点击 执行队列

行为：

  • 仅更新源节点自身的字段到目标节点（走 edit*Node）
  • 子节点不更新，如需同步子节点请手动逐个操作
  • 源与目标节点类型必须一致（按钮→按钮，菜单→菜单）
  • 字段/数据节点（type 4/5）的明细列表会一起覆盖，因为明细列表是字段/数据节点的核心配置
两种模式的区别：批量模式是「搬运整棵子树」，单点模式是「点对点覆盖单个节点」。单点模式不会自动更新子节点，需要更新子节点时请逐个操作。

同步策略（upsert）

插件不是盲目新增，而是先搜索目标树匹配已有节点，再决定新增还是更新：

节点类型匹配键说明
目录 (type=1)parentId + name同一父节点下名称唯一即匹配
菜单 (type=2)parentId + path路由地址是菜单的唯一标识
按钮 (type=3)parentId + perms权限字符不应重复
字段 (type=4)parentId + code字段编码唯一
数据 (type=5)parentId + code数据编码唯一
  • 匹配到 → 对比字段：有差异则调用 edit*Node 更新，一致则跳过不发送请求
  • 未匹配到 → 调用 add*Node 新增
  • 更新时目标已删除 → 自动降级为新增
  • 同步顺序：BFS（先父后子），确保子树 parentId 正确指向已创建的新节点
注意：如果源环境和目标环境的权限字符（perms）不一致（如带环境前缀差异），插件会将其判为新增而非更新。这种情况建议在目标页面上手动修改权限字符，而非通过插件同步。

界面详解

面板操作

  • 拖拽移动：按住蓝色圆形按钮拖动面板位置
  • 宽度缩放：拖动面板左边缘的蓝色手柄调整面板宽度（最小 500px）
  • 面板高度：自动为窗口高度的 80%，窗口缩放时跟随

源数据树操作

  • 勾选节点：父节点勾选 → 自动连带所有子孙；取消父节点 → 取消所有子孙
  • 半选状态：部分子孙已勾选时，父节点显示蓝色半选框
  • 全选/取消：点击树头部 ☑ 按钮
  • 展开/折叠：点击节点前的 ▶/▼ 箭头；点击树头部 ▼/▲ 批量操作
  • 搜索节点：输入关键字自动展开匹配路径，匹配节点高亮
  • 悬浮提示：鼠标悬停在节点上显示完整信息（perms/path/code/type/id）
  • 颜色标记：选中目标父节点后，勾选节点实时显示同步状态颜色

目标数据树操作

  • 选中目标父节点：点击节点高亮，底部显示选中路径
  • 只允许选中目录/菜单：按钮、字段节点不可作为父节点
  • 展开/折叠：点击 ▶/▼ 箭头（不会触发选中）

同步队列

  • 查看详情：点击 ▶ 展开，显示所有子节点及各自的同步状态标签
  • 移除任务：点击 ✕ 删除单条
  • 清空队列：点击「清空队列」删除全部

日志面板

  • 默认折叠：点击「▼ 展开」查看详细日志
  • 日志内容：每条任务的汇总结果（新增数/更新数/明细数/失败数）
  • 失败行：红色显示，包含具体错误信息

常见问题

Q: 点击采集后提示「获取资源树失败」？
A: 检查是否已打开应用的「资源」标签页（页面需先加载过资源树才能提取 appId 和 API 地址）。若仍失败，在工具栏手动输入 appId 后重试。
Q: 子节点挂错位置了？
A: 确保在目标数据中先采集了目标环境的数据。插件需要目标树来判断已有节点的 id，否则子节点 parentId 会 fallback 到根位置。
Q: 字段权限的明细没有同步过来？
A: 明细同步需要先拿到新建节点的 id（API 可能不返回）。如果节点创建成功但明细为空，展开日志确认是否有「明细同步失败」警告，然后重新采集目标数据后重试。
Q: 权限码变了，想更新而非新增？
A: 插件按权限码匹配，权限码变了就会识别为新节点。这种情况建议直接在目标页面手动编辑权限码字段，或在队列中观察颜色——如果标记为绿色（新增），说明不会更新已有节点。
Q: 面板消失了？
A: 插件只在 /MF_auth/ 路径的页面激活。从非权限页面进入或刷新后需重新打开。面板位置和宽度会自动保存到浏览器 localStorage。
Q: Token 需要手动填写吗？
A: 不需要。插件注入到页面上下文中，自动携带当前页面的 Admin-Token（从 localStorage 读取），与页面自身的请求完全一致，没有 CORS 问题。
Q: 同步会生成重复数据吗？
A: 不会。插件采用 upsert 策略：先在目标树中搜索匹配节点，找到则更新，找不到才新增。字段完全一致的节点会直接跳过（不发送请求）。
